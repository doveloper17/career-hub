# 현재 설계

이 문서는 공개 템플릿의 설계 계약이다. 개인별 구현 일지와 과거 대화는 포함하지 않는다. 컨셉·설치·경력 스키마·예제·승인 절차는 README에서 독립적으로 설명한다. 작업별 체크리스트는 `.local/WORK_LOG.md`에서 관리한다.

## 설계 계약

- Markdown 경력 원본과 JSON 지원 상태·출처·리뷰를 사용한다.
- 대표 이력서는 공통 저장 구조에서 kind=representative와 title로 구분한다. 회사·포지션·JD·키워드는 선택이며 일반 지원의 필수 입력은 유지한다. 실행기는 목적을 분석해 경력을 선택·표현한다. 모델 없는 career generate는 키워드가 없으면 사용 가능한 전체 경력을 최신순으로 선택한다. 대표 목록은 /resumes/이며 지원 건수에서는 제외하고 검증·리뷰·사람 승인·Git 검사는 공통으로 적용한다.
- 공개 템플릿에는 가상 데이터와 코드만 둔다. 실제 경력은 독립 비공개 저장소에 둔다.
- 경력은 `content/career/`, 이력서는 `content/applications/`에 저장한다. 사용자는 클론한 독립 비공개 저장소에서 가상 샘플을 실제 자료로 교체한다. `repository.json`은 Git 보호 정책을 설정한다.
- `lib/schema.mjs`는 형식, `lib/store.mjs`는 파일 조회, `lib/workflow.mjs`는 생성·검증·승인을 담당한다.
- Astro와 Node 어댑터로 요청마다 파일을 조회한다. 상세 경로를 정적 열거하지 않는다. 데이터 변경은 새로고침, 빌드 서버의 코드 변경은 재빌드로 반영한다.
- 웹은 읽기 전용이다. CLI로 지원 자료를 생성·변경한다. 동시 쓰기는 지원하지 않으므로 작성 담당 한 명이 순서대로 실행한다.
- 경력 기간은 YYYY-MM과 YYYY-MM-DD를 그대로 보존하며 월만 확인된 경우 일자를 만들지 않는다. 지원 생성일·마감일은 YYYY-MM-DD다.
- Markdown의 Mermaid 코드 블록은 HTML 정제 후 브라우저의 로컬 번들로 렌더링한다. strict 보안 설정과 htmlLabels=false를 사용하며 렌더링 실패 시 실행하지 않는 원문 코드를 유지한다.
- 회귀·live 테스트 입력은 tests/fixtures/template-content와 고정 허용 목록에서 가져온다. 실제 content 교체와 테스트를 분리하되 build의 validate는 현재 content를 검사한다.
- 생성 표현은 원문과 달라도 되며 확인된 사실의 의미를 보존해야 한다. 원본 확인·출처·본문 구조는 코드가 검사하고 모든 문장의 의미는 verifier의 claim_checks로 검토한다. 출처 ID 존재나 구조 PASS만으로 사실 검증 완료로 간주하지 않는다.
- 모든 경력은 현재 원본 해시와 일치하는 content/source-approvals 확인 기록이 있어야 사용한다. 기본 예시에는 원본 확인 완료를 가정한 기록을 포함한다. 콘텐츠 교체 시 기존 확인이 만료되며 본인 확인을 거친다. 별도 실행 모드나 가상/실제 구분 필드는 없다. visibility=private은 생성에서 제외한다. 다운로드에는 동일한 리뷰·최종 승인 검사를 적용한다.
- 제출용 다운로드는 현재 원본 검사·모든 항목 PASS 리뷰·사람 승인에 공통 검사를 적용한다. 화면 상태도 저장된 status만 믿지 않고 현재 검증 결과로 계산한다.
- 승인 해시는 실제 사용한 출처와 이력서/JD/분석/전략·안정 메타데이터에 연결한다. 관련 없는 경력 변경은 승인을 만료시키지 않는다. 반면 실행 입력 버전은 verified 전체 경력을 추적하며, 원본 해시는 파싱된 필드와 body를 대상으로 한다. 상세 범위는 docs/REVIEWS.md를 따른다.
- CLI 쓰기는 프로젝트 단위 잠금과 변경 전 백업으로 보호한다. 실패는 복원하며 강제 종료 시 잠금을 남겨 읽기/제출을 차단한다. 모든 작성 프로세스를 종료한 후 명시적으로 복구한다. 파일 직접 편집과 동일 OS 권한의 악의적 변경은 보호 범위 밖이다.
- 리뷰는 현재 문서 해시에 연결되고 사람이 최종 승인한다. JD·작성 전략·이력서·출처·경력 원본이 바뀌면 기존 리뷰/승인을 재검토한다.
- 고정본은 덮어쓰지 않는다. `submitted`는 로컬 고정본 보관이며 외부 제출을 뜻하지 않는다.
- 개인 기록은 `.local/`, 빈 양식은 `templates/work-log.md`에 둔다. 사용자별 절대 경로를 공개 소스에 넣지 않는다.
- `.codex/agents/`의 4개 역할을 `scripts/workflow.mjs` 실행기가 연결하고 단일 역할은 `scripts/agents.mjs`로 호출한다. 실행기는 상태·예산을 저장하고 표현 수정만 자동화한다. 사실 부족·최종 승인은 사람에게 남긴다. 세부 절차는 docs/EXECUTOR.md, 결과 계약은 lib/agent-contract.mjs, 기본 한도는 workflow-policy.json이다. 격리 검사 실패 시 모델을 호출하지 않는다.
- 작성과 두 리뷰는 문맥을 분리한다. 검토자에게 동일 버전의 원본·이력서·출처를 전달하고 서로의 판정을 숨긴다. 실행기가 두 결과·해시·필수 check·모든 claim_checks를 검증해 저장한다. 수동 호출은 총괄이 같은 계약으로 처리한다. 실행 불가를 자기 검토 PASS로 대체하지 않는다.
- 코드 구조 검사는 원본 확인·출처·본문 정합성과 필수 키워드의 근거를 검사한다. 리뷰 저장·승인·다운로드 게이트는 버전·필수 체크·문장별 검토 누락을 별도로 검사한다. AI 의미 검토는 과장·왜곡을 놓칠 수 있으며 두 PASS도 사실 오류가 없다는 보장이 아니다. 최종 사실성은 사람이 실제 경험과 대조한다.
- --review-only는 기존 초안의 최초 분석·작성을 생략하지만 FAIL의 표현 수정·리뷰 저장은 수행한다. 무변경 검토는 단일 역할 runner를 사용한다. 실행기 상태와 웹의 지원 metadata 상태는 별개다.
- 자동 수정은 업무별 최대 2회이며 CLI repair도 함께 센다. 수정한 버전은 코드 검사와 독립 리뷰를 다시 거친다. 원본·최종 사람 승인 및 Git 승인은 별도다.
- 기본 한도는 실행 시작 시 복사하며 모델·추론 설정은 각 호출 때 읽는다. workflow status는 마지막 저장 기록이며 완료 상태도 현재 승인 검사를 대신하지 않는다. 실행 잠금 해제와 콘텐츠 저장 롤백은 별도 명령이다.

## 현재 제공 범위

1. 경력 라이브러리, 지원 목록/상세, 출처 비교, Markdown 다운로드
2. JD 수동 입력, 키워드 매칭, 확인된 문장 추출·정렬
3. 스키마·출처·본문 구조 검사, 문장별 의미 검토 및 제한된 표현 수정
4. 검토자별 리뷰 결과 기록, 사람 승인, 제출본 로컬 고정
5. Secret 검사, 설치형 Git Hook, 개인 작업 기록 제외
6. 단계 자동 연결·중단 상태 저장·재개·호출 및 관측 토큰·시간 예산

생성 직후 검토 대기는 리뷰를 통과했다는 뜻이 아니다.
